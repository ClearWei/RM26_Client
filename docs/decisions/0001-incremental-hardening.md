# ADR 0001：采用行为优先的渐进式开源重构

- 状态：accepted
- 日期：2026-08-15
- 决策人：RM26 客户端维护团队

## 背景

客户端和模拟器是在赛季压力下持续演进的真实系统。当前实现已经覆盖比赛所需的通信、
视频、战术界面和异常切换，但同时存在巨型类、协议双源、工具入口重复、测试基线不全和
公开发布资料缺失等问题。

直接迁移到全新的目录和模块边界，会同时改变构建、链接、资源路径、QObject 生命周期和
运行脚本，难以判断回归来自哪一层。只整理 README 和目录外观，则无法解决线程、安全和
协议一致性风险。

## 决策

采用行为优先的渐进式方案：

1. 先冻结可复现的构建、测试、协议和运行时基线。
2. 优先修复现场动作授权、网络生命周期和公开信息边界。
3. 保持外部 signal、property、topic 和脚本入口不变，逐个提取内部职责。
4. 逻辑边界有测试后，再拆 CMake target 和迁移目录。
5. 公开发布采用内容白名单和干净历史，不直接将现有内部远程仓库切为 Public。

## 结果

正面影响：

- 每个提交影响面更小，回归更容易定位。
- 赛场行为和兼容入口可以在整理期间保持稳定。
- 架构文档、测试和真实编译边界能同步演进。
- 许可证、素材和敏感信息可以在发布前独立审查。

代价：

- 一段时间内会保留旧名称、兼容 facade 和部分重复结构。
- 目录不会立即呈现最终形态。
- 需要为历史行为补测试，短期工作量高于一次性移动文件。

## 备选方案

### 只做文档和目录清理

未采用。它能改善第一印象，但无法降低协议、线程和现场动作风险。

### 整体迁移到 `apps/client` 与 `apps/simulator`

现阶段未采用。跨目录、构建和运行入口的大范围变化缺少足够绿线保护。等编译边界和兼容
测试稳定后，可以通过新的 ADR 重新评估。

## 重新评估条件

满足以下条件后，可讨论更大规模的目录迁移或接口收敛：

- C++、模拟器和协议测试在受支持平台持续全绿。
- MQTT、视频线程和应用退出已有生命周期测试。
- 客户端与模拟器使用同一协议生成链。
- 关键 QML property、signal 和赛事命令有兼容测试。
- 公开内容白名单、许可证与素材权属已经确认。
